## Key Decisions
- **Single shared module `wikifetch.py`** instead of duplicating logic across scripts — easier to test, single source of truth, no circular imports (3 scripts can all import from it)
- **Stricter rule: ALL significant words must match** (not just ONE) — this is the key difference from the old `check_title_match` which matched on ANY word
- **First-paragraph as secondary signal** — handles edge cases where Wikipedia has a generic title (redirect) but the actual content is about the right person. Saves legitimate matches like "Muhammad" title + "Muhammad Zaki" first_para
- **Backward compat wrapper** for `check_title_match` — kept as thin wrapper calling `verify_wikipedia_match` to avoid breaking any future callers (none currently exist per explore agent)
- **Mocked data in regression test** — live API behavior changes over time, so the deterministic mock of historical corruption is more reliable for regression testing
- **Re-enrich pattern: reject + fallthrough to next source** — in `enrich_sanad.py`, if Wiki ID fails verification, fall through to Wiki EN; if EN also fails, fall through to Exa search (no early break)
