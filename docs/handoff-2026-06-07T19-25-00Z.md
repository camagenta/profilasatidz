## Key Decisions
- **Tmux untuk proses panjang**: SSH biasa punya timeout 2 menit. Tmux session persist di server, bisa di-detach/reattach. Untuk guardian ~3 menit cukup, tapi untuk future run dengan 200+ issue akan butuh tmux.
- **NFKC normalization**: Penting untuk nama Arabic. "الشيخ محمد موسى آل نصرSyaikh Muhammad Musa Alu Nasr" bisa punya representasi unicode berbeda. Sebelum NFKC, dianggap nama berbeda dan di-create dua kali.
- **Keep oldest, close rest**: Strategi cleanup untuk duplikat. Tutup sebagai duplicate (bukan delete) supaya history/reactions tetap ada untuk audit.
- **Race condition prevention**: 2 run bersamaan (dari nohup + tmux) bikin 30 duplikat. Untuk next time: kalau pakai nohup pastikan tunggu sampai selesai (tail log) sebelum luncurkan run kedua. Lebih aman: pakai tmux dan tunggu via `wait` atau `tmux wait-for`.

## Lessons Learned (jangan diulang!)
1. **Jangan jalankan dua long-running script bersamaan**: race condition menyebabkan duplikat. Pakai tmux + tunggu `wait`, atau cukup satu metode (nohup ATAU tmux, jangan dua-duanya).
2. **NFKC unicode normalization wajib untuk nama multilingual**: nama dengan Arabic + Latin mix bisa punya representasi unicode berbeda. Tanpa NFKC, dianggap nama berbeda.
3. **Search API paginate perlu careful counting**: `--paginate` di `gh api` mengembalikan semua halaman, tapi field `createdAt` null. Pakai `gh issue list --json` untuk data lebih reliable.
4. **TLS handshake timeout di GitHub API**: kadang terjadi. Retry dengan sleep 5-10 detik, atau gunakan batch kecil.
5. **Tmux untuk SSH long-running**: SSH punya timeout default 2 menit. Tmux session persist setelah SSH disconnect. Selalu pakai tmux untuk proses > 1 menit.
6. **Cleanup script perlu idempotent**: kalau ada sisa, harus bisa di-retry tanpa efek samping. `cleanup_duplicate_issues.py` skip issue yang sudah closed.
